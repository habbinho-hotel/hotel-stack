## 🐳 docker-compose.yml (Already minimal - 3 services)

The existing `docker-compose.yml` is already the simplest possible configuration:

```yaml
services:
  db:
    image: mariadb:11.4
    restart: unless-stopped
    environment:
      MARIADB_ROOT_PASSWORD: ${DB_ROOT_PASSWORD}
      MARIADB_DATABASE: ${DB_NAME:-habbo}
      MARIADB_USER: ${DB_USER:-polaris}
      MARIADB_PASSWORD: ${DB_PASSWORD}
      TZ: ${TZ:-UTC}
    volumes:
      - db-data:/var/lib/mysql
    healthcheck:
      test: ["CMD", "healthcheck.sh", "--connect", "--innodb_initialized"]
      interval: 10s
      timeout: 5s
      retries: 12
      start_period: 30s

  polaris:
    build:
      context: .
      dockerfile: docker/polaris/Dockerfile
    restart: unless-stopped
    depends_on:
      db: { condition: service_healthy }
    environment:
      HOTEL_DB_HOST: db
      HOTEL_DB_PORT: "3306"
      HOTEL_DB_NAME: ${DB_NAME:-habbo}
      HOTEL_DB_USER: ${DB_USER:-polaris}
      HOTEL_DB_PASSWORD: ${DB_PASSWORD}
      HOTEL_PUBLIC_URL: http://${HOTEL_HOST:-localhost}:${HTTP_PORT:-8080}
      JAVA_OPTS: ${JAVA_OPTS:--Xmx2g}
      TZ: ${TZ:-UTC}
    volumes:
      - polaris-data:/data
    ports:
      - "127.0.0.1:2096:2096"
    healthcheck:
      test: ["CMD", "bash", "-c", "exec 3<>/dev/tcp/127.0.0.1/2096"]
      interval: 15s
      timeout: 5s
      retries: 10
      start_period: 180s

  client:
    build:
      context: .
      dockerfile: docker/client/Dockerfile
    restart: unless-stopped
    environment:
      PUBLIC_URL: http://${HOTEL_HOST:-localhost}:${HTTP_PORT:-8080}
      PUBLIC_WS_URL: ws://${HOTEL_HOST:-localhost}:${EMU_PORT:-2096}
      PUBLIC_API_URL: http://${HOTEL_HOST:-localhost}:${EMU_PORT:-2096}
    volumes:
      - ./gamedata:/usr/share/nginx/gamedata:ro
    ports:
      - "127.0.0.1:8080:80"
```

**Key points:**
- **No Traefik, no Cloudflare, no complex NGINX** — just a bare `nginx:stable-alpine` serving static files
- **MariaDB** is internal-only (not published on host); only the Polaris container sees it
- **Polaris** exposes WebSocket/API on `127.0.0.1:2096` (localhost-only on host)
- **Client** serves the Octane build + `gamedata/` on `127.0.0.1:8080`

## 🔧 How to Build Octane + Renderer

The `setup.sh` already handles cloning the 3 repos and preparing `gamedata/`. The actual build happens when you run `docker compose build`.

But if you need to build locally (outside Docker) or re-build:

```bash
# 1. Clone the repos (setup.sh does this, or run manually):
git clone --depth 1 https://github.com/duckietm/polaris-emulator.git
git clone --depth 1 https://github.com/duckietm/Octane.git
git clone --depth 1 https://github.com/duckietm/Octane-Renderer.git

# 2. Install dependencies: Renderer FIRST, then Octane
cd Octane-Renderer && yarn install
cd ../Octane && yarn install && yarn build

# 3. The build outputs to:
#   Octane/dist/  (served by nginx as /assets/)
#   Octane-Renderer/dist/ (merged into Octane/dist during build)

# 4. Important config files are generated in public/configuration/:
#   - renderer-config.json
#   - ui-config.json
#   - client-mode.json
#   - hotlooks.jsonc, news.json, etc.
```

**The Dockerfile already does this automatically:**
```dockerfile
RUN cd Octane-Renderer && yarn install
RUN cd Octane && yarn install && yarn build
```

The `client/entrypoint.sh` then generates the JSON config files from the `.example` templates, replacing `localhost` with the actual URLs from `.env`.

## ⚙️ Generated Client Configuration Files

The `docker/client/entrypoint.sh` runs at container start and generates these files in `public/configuration/`, **only if they don't already exist** (so you can mount your own versions if needed):

### 1. `renderer-config.json`
- `socket.url`: WebSocket URL (ws://localhost:2096)
- `api.url`: API URL (http://localhost:2096)
- `asset.url`: http://localhost/gamedata (points to game assets)
- `gamedata.url`, `furnidata.url`, `productdata.url`, etc. all point to `/gamedata/`

### 2. `ui-config.json`
- `hotel.name`: "Camwijs" (from example)
- `emustats.endpoint`: ${api.url}/api/emustats
- `camera.url`: http://localhost/camera/photo/temp
- `toolbar.transparent`: true
- Various asset URLs pointing to `${asset.url}` and `/gamedata/`

### 3. `client-mode.json` (generated if missing)
```json
{
  "distObfuscationEnabled": false,
  "secureAssetsEnabled": false,
  "secureApiEnabled": false,
  "apiBaseUrl": "http://localhost:2096",
  "plainConfigBaseUrl": "http://localhost:8080/configuration/",
  "plainGamedataBaseUrl": "http://localhost:8080/gamedata/"
}
```

**These URLs come from the `.env` environment variables:**
- `PUBLIC_URL` → `plainConfigBaseUrl` and `plainGamedataBaseUrl`
- `PUBLIC_WS_URL` → `socket.url` in renderer-config
- `PUBLIC_API_URL` → `api.url` in renderer-config

To change them, just edit `.env`:
```
PUBLIC_URL=http://localhost:8080
PUBLIC_WS_URL=ws://localhost:2096
PUBLIC_API_URL=http://localhost:2096
```

Then rebuild and restart: `docker compose up -d --build`

## 🗄️ Polaris `config.ini` Configuration for MariaDB

The `docker/polaris/entrypoint.sh` generates `config.ini` at startup from `config.ini.example`, using environment variables. You **don't need to manually edit `config.ini`** — just set the `.env` variables correctly.

The critical variables (in `.env`):

```env
# Database connection (Polaris reads these into config.ini)
HOTEL_DB_HOST=db          # = the MariaDB service name in compose
HOTEL_DB_PORT=3306
HOTEL_DB_NAME=habbo
HOTEL_DB_USER=polaris
HOTEL_DB_PASSWORD=SECRET  # defined in .env by setup.sh

# TJ
TZ=UTC

# Server
HOTEL_HOST=localhost
HTTP_PORT=8080
EMU_PORT=2096
```

**What the entrypoint does automatically:**
1. Copies `config.ini.example` → `config.ini`
2. Replaces `db.hostname`, `db.port`, `db.database`, `db.username`, `db.params` using the `HOTEL_DB_*` env vars
3. Sets `game.host=0.0.0.0` (accepts connections from any IP)
4. Sets `nitro.secure.master_key` from the secrets volume (`/data/secrets.env`)
5. Disables `login.remember.cookie.secure` for http (since we're using `http://localhost`)

**No manual `config.ini` editing needed.** Just ensure `.env` has the correct DB credentials.

## 🚀 Final Commands to Start Everything

```bash
# 1. Prepare everything (clones repos, creates .env, sets up gamedata/ basics)
./setup.sh

# 2. Build and start all containers
docker compose up -d --build

# 3. Wait for Polaris to start (logs show "Polaris has successfully loaded.")
docker compose logs -f polaris

# 4. Open your browser
open http://localhost:8080
```

**First-time flow:**
1. `setup.sh` clones `polaris-emulator`, `Octane`, `Octane-Renderer` to the project root
2. Creates `.env` with random DB passwords
3. Copies basic assets from `polaris-emulator/Assets/` into `gamedata/`
4. `docker compose build` compiles the Polaris JAR and the Octane build
5. `docker compose up -d` starts all services
6. Polaris startup:
   - Creates the `habbo` schema automatically (migrations run once)
   - Generates `config.ini` from the template + env vars
   - Starts the JVM on port 2096
7. Client startup:
   - Installs yarn deps for Renderer + Octane
   - `yarn build` Octane
   - Generates `public/configuration/*.json` from `.example` templates
   - Starts nginx serving `http://localhost:8080`

**Access:**
- Hotel client: `http://localhost:8080`
- WebSocket/API (from client): `ws://localhost:2096` / `http://localhost:2096`
- MariaDB (if needed): `docker compose exec db sh -c 'mariadb -uroot -p"$MARIADB_ROOT_PASSWORD" "$MARIADB_DATABASE"'`

## 📦 Assets: Where to Get Them & Folder Structure

The `gamedata/` folder is the critical piece. Here's what goes where:

| Folder in `gamedata/` | Content | Source |
|---|---|---|
| `config/` | FurnitureData.json, ProductData.json, FigureData.json, FigureMap.json, EffectMap.json, HabboAvatarActions.json, ExternalTexts.json, UITexts.jsonc | All-in-1 Converter or extract from hotel bundle |
| `furniture/` | `.hab` bundles (furniture) | All-in-1 Converter → `Assets/furniture/` |
| `clothes/` | `.hab` bundles (clothing) | All-in-1 Converter → `Assets/clothes/` |
| `effects/` | `.hab` bundles (effects) | All-in-1 Converter → `Assets/effects/` |
| `pets/` | `.hab` bundles (pets) | All-in-1 Converter → `Assets/pets/` |
| `room/` | `.json` room definitions | All-in-1 Converter → `Assets/room/` |
| `icons/` | `.png` icons (catalog) | All-in-1 Converter → `Assets/icons/` |
| `sounds/` | `.mp3` sounds | All-in-1 Converter → `Assets/sounds/` |
| `c_images/` | Group badge parts `.png` | From `polaris-emulator/Assets/badgeparts/` (setup.sh copies these) |
| `images/` | Catalog images `.png` | From `polaris-emulator/Assets/images/` (setup.sh copies these) |

### How to get the assets:

**Option A — All-in-1 Converter (recommended):**
1. Download and run the [All-in-1 Converter](https://github.com/duckietm/all-in-1-converter)
2. It converts hotel `.nitro`/`.hab` archives into the folder structure above
3. Copy the generated folders into `./gamedata/`

**Option B — All-in-1 Manager (GUI):**
1. Use the "Assets → Habbo assets" section
2. Download and extract to `./gamedata/`

**Option C — From existing hotel bundle:**
1. If you have a running hotel with a CMS, extract the `gamedata/` folder from the hotel's deployment
2. Copy the `config/`, `furniture/`, `clothes/`, etc. folders into `./gamedata/`

### Minimal gamedata (already prepared by setup.sh):

The `setup.sh` already copies the basic images and badgeparts that come in the Polaris Emulator repo:

```bash
# These are copied automatically by setup.sh:
cp -rn polaris-emulator/Assets/images/     gamedata/images/
cp -rn polaris-emulator/Assets/badgeparts/ gamedata/c_images/groupbadge/badgeparts/
```

You'll need to add the rest (config JSONs, .hab bundles, catalog assets) yourself via one of the methods above.

## ⚠️ Known Limitations & Edge Cases

1. **Assets are the hardest part** — The converter generates hundreds of files. Start with a minimal set (essential furniture + configs) and add more later.

2. **Polaris DB schema auto-creation** — On first start, Polaris creates the `habbo` schema automatically. No SQL import needed.

3. **WebSocket connectivity** — The client connects to `ws://localhost:2096`. If you access the hotel from another machine on the network, update `.env`: `HOTEL_HOST=<machine-ip>` and `BIND_ADDR=0.0.0.0`, then restart.

4. **No HTTPS by default** — Cookie `secure` flag is disabled for `http://localhost`. If you add Traefik/NGINX reverse proxy with HTTPS later, you'll need to re-enable it.

5. **Port conflicts** — If port 8080 or 2096 are already in use on your host, change the `.env` values.

6. **Memory —** The Polaris container defaults to `-Xmx2g`. Adjust `JAVA_OPTS` in `.env` if you need more memory.
